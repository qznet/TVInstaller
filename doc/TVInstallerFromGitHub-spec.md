## 1. 产品概述

### 1.1 产品定位
**TV Installer from GitHub** 是一款运行于 Android TV 平台的工具类应用。其核心价值在于：

- 通过 **GitHub** 仓库浏览、查找并下载 **APK 安装包**
- 一键完成 **APK 安装**，实现从代码仓库到电视应用落地的闭环
- 面向 TV 大屏场景，**全遥控器操作**，交互路径极简

### 1.2 核心场景
1. 用户打开应用，浏览预配置的仓库列表或个人收藏
2. 进入仓库后，通过遥控器快速遍历文件和 release 资源
3. 定位到 `.apk` 文件，点击 OK 触发下载 → 自动安装
4. 其他文件（源码、文档等）以内嵌浏览器方式预览

### 1.3 目标用户
- 安卓 TV 开发者 / 极客用户
- 习惯从 GitHub 获取应用安装包但苦于电视端操作不便的用户
- 需要频繁安装/测试 APK 的 TV 应用测试人员

## 2. 技术架构

### 2.1 技术栈

| 层级 | 选型 | 说明 |
|------|------|------|
| 语言 | Java | 兼容 Android 4.2+，稳定成熟 |
| 最低 SDK | API 17 (Android 4.2) | 覆盖绝大多数现存 TV 设备 |
| 目标 SDK | API 34 (Android 14) | 平衡新特性与兼容性 |
| 网络 | OkHttp 3.12.x | HTTP 请求、自动线路切换、文件下载和断点续传 |
| 浏览器内核 | WebView (系统内置) | 用于内嵌渲染 GitHub 页面，不依赖第三方解析库 |
| 本地存储 | SharedPreferences + 文件存储 | 收藏列表、配置缓存 |
| 解析 | 不解析 HTML！ | 仅通过 WebView 展示，避免 GitHub 结构变更导致失效 |

### 2.2 架构分层

```
┌─────────────────────────────────────────────────┐
│                    UI 层 (TV Leanback)           │
│   - 仓库列表 (RecyclerView + 焦点管理)           │
│   - WebView 容器 (全屏/分屏)                    │
│   - 下载/安装进度 Toast/Dialog                  │
└─────────────────┬───────────────────────────────┘
                    │
┌─────────────────▼───────────────────────────────┐
│              业务逻辑层 (ViewModel / Presenter)   │
│   - 数据源管理 (预配置 + 收藏 双源合并)          │
│   - 同步服务 (拉取 raw 配置)                     │
│   - 下载管理 (队列/状态/重试)                    │
│   - 安装触发 (调用系统安装器)                    │
└─────────────────┬───────────────────────────────┘
                    │
┌─────────────────▼───────────────────────────────┐
│                数据层 (Repository)                │
│   - 预配置数据源 (本地 data/ 目录下 raw 文件)    │
│   - 收藏数据源 (SharedPreferences)               │
│   - 缓存管理 (APK 临时存储)                     │
└─────────────────────────────────────────────────┘
```

### 2.3 关键约束
- **不解析 GitHub 网页 DOM**：所有内容展示通过 WebView 完成，仅封装遥控器按键映射。这样即使 GitHub 前端更新，应用依然可用。
- **数据源分离**：预配置列表通过 raw 文件更新，收藏列表本地持久化，两者互不干扰。
- **下载路径**：APK 下载至 `/sdcard/Android/data/com.tvig.installer/cache/`，安装完成后自动清理。

### 2.4 国内网络自动加速
- 配置同步与 APK 下载统一通过 `GitHubRouteManager` 生成候选线路。
- 默认顺序为国内 HTTPS 中转节点，全部失败后回退 GitHub 原始地址；上次成功线路在下次请求时优先使用。
- 任一线路出现连接超时、HTTP 错误、断流或返回非 APK 内容时，后台自动切换下一线路，用户无需使用遥控器选择。
- APK 下载保留 Range 断点续传，并在完成后校验 ZIP/APK 文件头，避免代理错误页被当作 APK 安装。
- WebView 继续加载 GitHub 原始页面以保持完整浏览功能；直连失败时自动尝试本地网页缓存。

## 3. 交互规范 (遥控器)

### 3.1 按键映射表

| 遥控器按键 | 交互行为 |
|-----------|----------|
| **⬆ / ⬇** | 在列表/文件条目间上下切换焦点 |
| **⬅ / ➡** | 目录层级进出（➡ 进入目录/Release；⬅ 返回上级） |
| **OK (确认)** | 选中当前焦点项：仓库→进入；APK→下载安装；其他文件→预览 |
| **MENU (菜单)** | 收藏当前仓库（若已收藏则取消收藏） |
| **HOME** | 返回顶层仓库列表（清空浏览栈） |
| **BACK** | 返回上一级（与 ⬅ 类似，但更侧重页面回退） |

### 3.2 焦点反馈
- 当前焦点项必须带有 **3px 高亮边框**（色值 `#58A6FF`）
- 焦点移动动画 ≤ 100ms，避免延迟感
- 列表滚动跟随焦点（自动滚动到可视区域）

### 3.3 反馈提示
- 下载开始：底部弹出 Toast “开始下载：xxx.apk”
- 下载完成：Dialog “下载完成，是否安装？” → 点击 OK 调起系统安装器
- 安装完成：Toast “安装成功” 或 系统安装器自带反馈
- 错误情况：Toast 简明提示（如“网络异常”“存储空间不足”）

## 4. 数据源设计

### 4.1 数据源类型

| 类型 | 来源 | 存储位置 | 更新方式 |
|------|------|----------|----------|
| **预配置 (Preset)** | 开发者维护的 raw 文件 (GitHub) | `/data/data/com.tvig.installer/files/preset.txt` | 用户手动点击“同步”拉取 |
| **收藏 (Favorite)** | 用户主动收藏 | `SharedPreferences` | 用户点击 MENU 增删 |

### 4.2 预配置数据格式 (preset.txt)
- **编码**：UTF-8
- **每行一条**，格式如下：
  ```
  <owner>/<repo> = <可选描述>
  ```
- **示例**：
  ```
  user1/awesome-apk = 精选安卓工具集
  devteam/tv-utils = TV 专用工具
  opensource/reader
  ```
- **解析规则**：
  - 以 `=` 分割，左侧为仓库短链接（必填），右侧为描述（可选）
  - 忽略空行和首尾空格
  - 若没有 `=` 或等号右侧为空，则不显示副标题

### 4.3 收藏数据格式
- 仅存储仓库短链接字符串（如 `user1/awesome-apk`）
- 列表展示时，若仓库同时在预配置中有描述，优先显示预配置描述；否则只显示仓库名

### 4.4 列表展示规则
- 主标题：仓库名（如 `user1/awesome-apk`）
- 副标题：若有描述则显示，颜色 `#8B949E`
- 角标：左上角显示 “预配置” / “收藏” 标签区分来源
- 排序：预配置在前（按配置顺序），收藏在后（按添加时间倒序），中间用分割线

## 5. 功能模块详述

### 5.1 同步 (Sync)
- **入口**：列表页顶部 “同步” 按钮
- **行为**：
  1. 使用自动线路列表请求预设的 raw 地址（如 `https://raw.githubusercontent.com/xxx/preset.txt`）
  2. 下载并覆盖本地 `preset.txt`
  3. 重新加载列表
- **失败处理**：逐条切换中转线路和 GitHub 原站；全部失败后保留旧数据并使用内置配置。

### 5.2 仓库浏览
- 点击仓库 → WebView 加载 `https://github.com/<owner>/<repo>`
- WebView 内支持遥控器方向键滚动页面（模拟鼠标滚轮）
- 特殊快捷跳转（通过 WebView 注入 / 或 URL 拼接）：
  - 按 ➡ 可快速跳转到文件列表区域
  - 按 菜单 可快速跳转到 Release 区块
  - *具体实现方案需 WebView 团队进一步评估（可通过 JS 接口辅助）*

### 5.3 APK 下载与安装
- **触发**：用户焦点在 `.apk` 链接上时按下 OK
- **流程**：
  1. 获取下载 URL（从 WebView 当前页面的链接或通过 JS 提取）
  2. 自动选择上次成功线路并开始下载，失败时切换线路并从 `.part` 文件继续
  3. 下载完成 → 弹出安装确认对话框
  4. 用户确认 → 调用 `Intent.ACTION_VIEW` 打开 APK 文件，调起系统安装器
  5. 安装完成后，自动删除缓存 APK 文件（或下次启动时清理）
  6. 下载完成后校验 APK ZIP 文件头，错误页面或无效文件不会进入安装流程
- **约束**：
  - 需申请 `WRITE_EXTERNAL_STORAGE` (Android 4.2) 或使用 `getExternalFilesDir` (Android 10+)
  - Android 8.0+ 需声明 `REQUEST_INSTALL_PACKAGES` 权限

### 5.4 文件预览 (非 APK)
- 对于 `.md`、`.txt`、`.json`、源码文件等，直接在 WebView 中打开 GitHub 的渲染页面
- 无需额外解析，完全依赖 GitHub 的展示能力

## 6. UI / UX 设计规范

### 6.1 屏幕适配
- 以 1920x1080 (Full HD) 为设计基准
- 所有尺寸使用 dp，字体使用 sp
- 确保在 1280x720 及 3840x2160 (4K) 下清晰可读

### 6.2 配色方案 (暗色主题)

| 用途 | 色值 |
|------|------|
| 背景 (主) | `#0D1117` |
| 背景 (卡片) | `#161B22` |
| 边框/分割线 | `#30363D` |
| 主文字 | `#E6EDF3` |
| 次级文字 | `#8B949E` |
| 高亮 (焦点) | `#58A6FF` |
| 按钮/主色 | `#238636` |
| 警告/下载 | `#D29922` |

### 6.3 字体
- 系统默认无衬线字体 (Roboto / Noto Sans)
- 标题：20sp 粗体
- 列表主标题：18sp 常规
- 列表副标题：14sp 常规
- 提示文字：13sp 常规

## 7. 开发约束与里程碑

### 7.1 兼容性清单
- [ ] Android 4.2 (API 17) ~ Android 14 (API 34) 兼容测试
- [ ] 主流 TV 设备 (NVIDIA Shield, Mi Box, 索尼/三星电视等)
- [ ] 支持 armv7a / arm64-v8a 架构
- [ ] 安装包体积 ≤ 8MB (不含 WebView 内核)

### 7.2 性能指标
- 列表渲染 ≤ 100ms
- 焦点切换响应 ≤ 50ms
- WebView 首次加载 ≤ 3s (百兆网络)
- 下载支持断点续传，最大支持 2GB 文件

### 7.3 里程碑

| 阶段 | 任务 | 周期 |

| M1 | 基础框架 + 列表展示 (双数据源) | 2周 |
| M2 | WebView 集成 + 遥控器按键映射 | 2周 |
| M3 | 下载 + 安装功能 | 1.5周 |
| M4 | 同步 + 收藏 + 异常处理 | 1周 |
| M5 | 兼容性测试 + 稳定性优化 | 1.5周 |
| M6 | 上架准备 (商店素材、隐私政策) | 0.5周 |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| GitHub Web 结构变动 | 遥控器跳转失效 | 依赖 WebView 原生滚动，减少 JS 注入依赖；定期维护 |
| APK 下载 URL 获取困难 | 无法触发下载 | 通过 WebView 的 `shouldOverrideUrlLoading` 拦截 `.apk` 链接 |
| 系统安装权限限制 | 安装失败 | 引导用户手动开启 “允许安装未知来源” |
| 预配置 raw 地址失效 | 新用户无数据 | 内置 fallback 默认列表，硬编码在 APK 中 |
| 存储权限 (Android 11+) | 无法写入外部存储 | 使用应用私有目录，无需额外权限 |

## 9. 附录

### 9.1 预配置文件维护指南
- 开发者需在 GitHub 上维护一个公开仓库，存放 `preset.txt`
- 更新后用户端点击“同步”即可生效
- 建议每季度审核一次列表有效性

### 9.2 收藏数据存储结构 (SharedPreferences)
```json
{
  "favorites": [

    "mike/games-repo"
  ]
}
```

```
IDLE → DOWNLOADING → DOWNLOADED → INSTALLING → INSTALLED
                ↓              ↓
              ERROR          RETRY
```
